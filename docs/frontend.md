# Веб-клиенты и основа для приложений

## Два адреса и две сборки

Гостевой сайт: https://vercel-site-puce-two.vercel.app/. Кабинет администраторов и управляющих: https://tynys-staff.vercel.app/staff/login.

Оба клиента используют Vue/FSD и один контракт Django API. `vite.config.js` выбирает `#surface-routes` до сборки: `routes-public.js`, `routes-staff.js` либо `routes-combined.js`. Public-сборка не содержит страниц управления; staff-сборка не содержит каталога/регистрации гостя. Квитанции нужны обоим клиентам. `scripts/check-surfaces.mjs` проверяет manifest обеих сборок. Разделение интерфейсов не заменяет серверные права.

| Команда | Назначение | Артефакт |
| --- | --- | --- |
| `npm run dev` | Оба интерфейса локально | localhost:4173 |
| `npm run build` | Combined для локальной проверки | dist/site |
| `npm run build:public` | Гостевой сайт | dist/site |
| `npm run build:staff` | Кабинет сотрудников | dist/staff |
| `npm run build:surfaces` | Обе сборки и проверка их границ | оба каталога |

`VITE_PUBLIC_URL` задаёт внешний адрес гостевого сайта в кабинете. `VITE_STAFF_URL` задаёт адрес входа сотрудников на гостевом сайте. Это публичные build-time параметры, а не секреты. `VITE_DATA_MODE=api` включает HTTP, по умолчанию используется demo. `VITE_API_BASE=/api` — рекомендуемая граница прокси. `VITE_APP_SURFACE` может явно переопределить режим; допустимы только public/staff/combined/mobile/mobile-staff.

Для Git-connected Vercel public-проекта используется `vercel.json`; для staff-проекта нужны команда `npm run build:staff`, output `dist/staff` и правила `vercel.staff.json`. Текущая production-публикация выполнена CLI из подготовленных статических артефактов. У public-проекта наблюдается работающая GitHub-интеграция с PR preview; staff-проект пока публикуется CLI. В Vercel production/preview сохранены публичные `VITE_STAFF_URL` для гостевого проекта и `VITE_PUBLIC_URL` для staff-проекта. В публикуемые файлы не входят backend, `.env`, исходная архитектура или LikeC4.

На разных origins браузерное demo-хранилище **раздельное**. Созданная гостем бронь на публичном адресе не появится в демо-кабинете другого адреса/устройства. Для общих записей необходимо опубликовать Django/PostgreSQL и собрать оба сайта в API-режиме. Нельзя решать это копированием localStorage или клиентских ролей между доменами.

## Сессии и сетевой контракт

Веб использует cookie-сессии и CSRF. Каждый сайт проксирует `/api` к одному Django; управляемые файлы выдаются через `/api/media/files/:id` с проверкой доступа. Прямой публичный proxy к private bucket не нужен. Реальные origins должны быть явно разрешены сервером; HTTPS, secure cookies и доверенные proxy настраиваются при размещении. Сотрудник входит через staff User, гость — через отдельный GuestAccount. Подтверждённый телефон нельзя изменять обычным PATCH профиля.

После регистрации текущая анонимная история переносится в новый аккаунт. Вход в существующий аккаунт не присоединяет чужую историю по совпадению телефона. Сброс пароля отзывает прежние гостевые сессии. Квитанции/оплата/профиль проверяют владельца на сервере. Подробные маршруты: [api-contract.md](api-contract.md).

Сейчас проверка телефона работает через явно обозначенный demo OTP. Реальная доставка ещё не реализована; сервер выдаёт/принимает demo-коды только при `DEBUG=True` и `GUEST_AUTH_DEMO_OTP=True`. Публичный demo не подтверждает владение реальным номером и предназначен для вымышленных данных.

## Локализация и загрузка

RU/KK/EN: `shared/i18n`, JSON namespaces common/auth/public/staff. Язык хранится в инфраструктуре i18n, компоненты не обращаются к localStorage. Проверяются одинаковые ключи, параметры `{name}`/`{0}`, компиляция сообщений и статические обращения. Указанные владельцем названия/описания объектов не переводятся автоматически. API передаёт стабильные коды ошибок; интерфейс переводит известные коды и общие HTTP-ошибки. Серверный PDF сейчас на русском; в browser-demo PDF использует выбранный язык.

Главная показывает каталог без дат; плавающая кнопка открывает native dialog с картой. Leaflet и тайлы загружаются при открытии карты. Даты выбираются в профиле санатория/номера. Escape закрывает карту, фокус возвращается на кнопку; ошибка тайлов не блокирует каталог. Ошибка загрузки chunk после обновления сайта показывает явную кнопку перезагрузки.

## Мобильные приложения

Серверные правила брони, денег, прав и владельца независимы от Vue. Этот API можно использовать при создании iOS/Android клиентов; текущие сайты сами по себе не являются готовыми приложениями магазинов. Сейчас сохраняется модульный Django-монолит, чтобы транзакции бронирования и возврата оставались атомарными. Разделять его на сервисы до измерений нагрузки не требуется.

Сервер уже предоставляет `/api/v1` и отдельные гостевые mobile-сессии: короткий access token, ротация refresh token, отзыв устройства и семейства при повторном использовании токена. Они используют те же правила бронирования и владельца данных; Bearer не даёт доступа сотрудника. Контракт и ограничения: [mobile-api.md](mobile-api.md).

Два отдельных iOS приложения реализованы на Capacitor: гостевое и рабочее. Маршруты/сборки разделены, токены хранятся в Keychain; инструкции и ограничения: [ios.md](ios.md). До релиза остаются OpenAPI и проверки совместимости, native-регистрация/сброс с настоящим SMS, удаление аккаунта, push/deep links, Android/Keystore и проверки на физических устройствах. Доступы и критерии запуска: [production-readiness.md](production-readiness.md).

## Файлы и фотография гостя

`MediaEditor` принимает файлы с устройства: JPEG/PNG/WebP до 8 MiB, MP4/WebM до 40 MiB для каталога. Санаторий нужно сначала сохранить, чтобы сервер мог проверить область доступа управляющего. В профиле зарегистрированного гостя можно загрузить, заменить и удалить аватар. Ошибки/ограничения переведены на RU/KK/EN; во время запроса повторное действие блокируется.

API-режим отправляет multipart через `shared/api`; права, реальный тип и размер проверяет Django. В demo Blob хранится отдельно в IndexedDB, а не в localStorage; транспорт восстанавливает временные object URL для отображения и сохраняет устойчивые ссылки в метаданных. Demo имеет лимит 100 MiB, очистку заброшенных загрузок и освобождение object URL. Такие файлы остаются только в браузере конкретного origin.
