## Действующие правила

Путь гостя: **категория или карта → санаторий → даты/гости → конкретный номер → тариф → временное удержание → демонстрационная оплата → автоматически оформленная бронь**. Даты не являются условием поиска на главной странице.

Бронь и оплата имеют независимые статусы. Подтверждение разрешает оплату; неуспешная оплата не отменяет бронь. Автоматического срока оплаты или истечения заявки сейчас нет. Отмена освобождает номер, даже когда возврат равен нулю.

Стоимость — целые тенге. Для каждой ночи используется цена номера из непересекающегося периода `[start, end)` либо базовая цена вне периодов. Добавляется надбавка тарифа × платные гости; скидка округляется 0,5 вверх отдельно за ночь, итог — сумма ночей. Сотрудник может включить бесплатный тариф детям 0–2 лет; стоимость номера сохраняется, дети входят во вместимость, нужен хотя бы один взрослый. Возраст задаётся на дату заезда. Снимок хранит политику и `nightlyBreakdown`; при разных ценах `nightly=null`, нельзя умножать цену первой ночи на срок. Старые брони не пересчитываются.

Время заезда и часовой пояс видны на сайте и фиксируются в заявке. Правила возврата согласованы пользователем:

| Осталось до сохранённого времени заезда    | Возвращается от оплаченной суммы |
| ------------------------------------------ | -------------------------------- |
| 48 часов или больше                        | 100%                             |
| От 24 часов включительно до 48 часов       | 70%                              |
| Меньше 24 часов, включая наступивший заезд | 0%                               |

Точно 24 часа дают 70%, 48 часов — 100%. Сумма возврата округляется вниз до целого тенге. Сейчас правило одинаково для отмены гостем и сотрудником; исключение для отмены по вине санатория не согласовано. Предпросмотр не фиксирует время: окончательный расчёт выполняется сервером при отмене и может измениться на границе периода. После отмены сохранённый результат не пересчитывается.

**Kaspi здесь — название демонстрационного сценария.** Приложение не подключено к API Kaspi, не создаёт банковский QR, не принимает платёжные реквизиты и не переводит деньги. Таблицы хранят результаты симуляции. Реальное подключение потребует отдельного договора/контракта провайдера, подтверждения платежей и согласованных условий.

## Две среды данных

- `demo`: браузерный каталог/история в localStorage, выбор демонстрационного сотрудника, фиксированный Asia/Almaty. Данные изменяемы через инструменты браузера; синхронизации устройств нет.
- `api`: Vue обращается к Django/PostgreSQL; сервер проверяет права, цену и доступность. Гость может работать анонимно либо войти в отдельный аккаунт по телефону/паролю; сотрудники входят по email/паролю. Проверка номера пока использует явный DEMO-код, оплата остаётся симулятором.

Медиа API пишет файлы на локальный диск. Фотографии проверяются и перекодируются; MP4/WebM проверяются по размеру и заголовку. Облачного медиасервиса с квотами, анализом безопасности, проверкой длительности и транскодированием видео ещё нет.

## Профиль, история, квитанции и работа с проживанием

| Область          | Реализовано в коде                                                                                                                                       | Где изменять                                                                 |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Профиль гостя    | Имя/телефон, история заявок, проживаний и оплат своей анонимной сессии либо гостевого аккаунта; ссылки на квитанции                                       | `pages/guest-profile`, `/api/profile`, `GuestProfile`                        |
| Аккаунт гостя    | Регистрация/вход по телефону и паролю, DEMO-код подтверждения/сброса, сохранение своей анонимной истории; API даёт доступ с другого устройства             | `pages/guest-auth`, `/api/guest-auth/*`, `GuestAccount`                     |
| Гость в кабинете | Управляющий видит контакт и брони гостя только по своему санаторию; администратор — по доступной платформе                                               | `pages/staff-guest`, `/api/guests/:id`                                       |
| Заселение/выезд  | Отдельный учёт not_arrived → in_house → checked_out; для подтверждённой оплаченной брони. Заселение в даты проживания; после заселения отмена недоступна | `pages/workspace`, `booking/services.py`                                     |
| Демо-квитанции   | Страница по оплате, скачивание PDF и передача файла через системный диалог при поддержке браузером; отдельная информация о возврате                      | `pages/receipt`, `features/payment-receipt`, `commerce/receipts.py`          |
| Аналитика        | Период и сравнение с предыдущим, дни/недели/месяцы, заявки, демонстрационные поступления/возвраты, отзывы, разрез по санаториям и номерам                | `pages/analytics`, `booking/analytics.py`, `app/providers/demo-analytics.js` |

Профиль может принадлежать анонимной сессии или зарегистрированному гостю. Регистрация сохраняет только историю текущего анонимного владельца; вход в существующий аккаунт не объединяет истории по телефону. Подтверждённый в текущем demo-процессе телефон аккаунта нельзя заменить редактированием профиля; реальная SMS-проверка ещё не подключена. Сброс пароля отзывает гостевые сессии. Исторические сведения брони/квитанции сохраняются, сотрудник не получает историю гостя в чужих санаториях. Досрочный выезд фиксирует операционное состояние, но не сокращает забронированный диапазон и не создаёт автоматического возврата.

Пользователь уточнил: в конечном продукте чек должен приходить **от Kaspi**. Сейчас есть только наша явно обозначенная демо-квитанция (`source: demo`), не банковский и не фискальный чек. В реальной интеграции нужно получать и сохранять документ/ссылку провайдера после его подтверждения; такой API ещё не подключён. Исходные поля демо-квитанции фиксируются при оплате, без телефона. После возврата исходная сумма сохраняется, сведения о возврате добавляются отдельно. Старые оплаты без снимка получают пометку восстановления при первом открытии. Доступ к странице/PDF — владельцу и сотруднику его санатория; публичной ссылки с доступом к персональным данным нет. Передача файла выполняется только действием пользователя.

## Семантика аналитики

`/staff/analytics` показывает события выбранного периода в Asia/Almaty; по умолчанию последние 28 дней. Можно выбрать до 366 дней, сутки/недели с понедельника/месяцы. Предыдущий период имеет такое же число дней. Пустые интервалы отображаются нулями, а не вымышленными значениями.

- **Заявки и стоимость заявок:** по дате создания брони, включая затем отклонённые/отменённые. Это не выручка; распределение статусов показывает их текущее состояние.
- **Демо-поступления:** первоначальная сумма успешной симуляции оплаты по дате оплаты, включая впоследствии возвращённые платежи.
- **Демо-возвраты:** по дате отдельного события возврата. Поступления минус возвраты могут быть отрицательными, если возврат произошёл в другом периоде.
- **Отзывы:** количество всех созданных отзывов; средняя оценка только одобренных отзывов этого периода. Нет оценок — пустое значение, не ноль.

Показатель поступлений за вычетом возвратов **не является прибылью**: расходы, налоги и комиссии не учитываются. Разрезы включают неактивные объекты и ограничены первыми 500 строками по этому показателю с пометкой ограничения; общие суммы и график учитывают весь разрешённый набор. Управляющий видит только свой санаторий. В старых браузерных данных без даты возврата событие исключается из периодных сумм и показывается предупреждение о неполных данных.

Текущие ограничения: 1–4 гостя, 1–30 ночей, один физический номер в заявке, один санаторий у управляющего. Workspace загружает весь доступный каталог/брони и последние 500 событий/отзывов; публичные отзывы ограничены последними 100. Это ограничения текущего этапа, а не окончательного масштаба платформы.

Комиссия платформы задаётся администратором отдельно для каждого санатория (0–100%, до двух знаков). Пусто означает «не настроено», а не 0%. Ставка и расчёт от итоговой суммы заказа фиксируются при создании; изменение настроек действует на новые заказы. Расчёт не является банковским разделением платежа, прибылью или выплатой санаторию. После возврата необходима финансовая сверка; комиссию банка и правила удержания/возврата комиссии ещё требуется согласовать.
