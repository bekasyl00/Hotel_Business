## Объём текущего этапа

Два самостоятельных приложения Capacitor 8 используют существующие Vue/FSD интерфейсы и общий Django `/api/v1`. Guest (`kz.tynys.booking`, `android/`) не содержит страниц сотрудников; staff (`kz.tynys.staff`, `android-staff/`) сохраняет серверные роли и tenant scope. Сборки используют bundled assets, не удалённый `server.url`. Это продолжение согласованной архитектуры iOS, а не второй backend или перенос данных в телефон.

Минимум: Android 7.0 (API 24), актуальный WebView/Chrome 107+. Для устаревшего WebView предусмотрена встроенная страница обновления на ru/kk/en; веб-сборка явно учитывает Chrome 107 и Safari 16.

Нативный слой отвечает за AndroidKeyStore, передачу файлов, камеру, системную навигацию и безопасные области экрана. Платёжные, возрастные и финансовые правила остаются на сервере. Android Emulator проверяет APK на виртуальном устройстве; он не превращает сайт в приложение — упаковку выполняет Capacitor.

## План и критерии проверки

1. Отдельные Android-проекты с API36, актуальными иконками и ограниченными разрешениями.
2. Совместимый `TynysKeychain` bridge: AndroidKeyStore AES-GCM, ciphertext в no-backup storage, раздельные UID двух приложений, без токенов в preferences/localStorage/logs.
3. Защищённые release-команды и APK для установки, AAB для Google Play. Подпись только из закрытой локальной конфигурации, без ключей в Git.
4. Проверка обеих сборок, реального Keystore на эмуляторе, каталога/навигации, API-сессии, границ аудиторий и отсутствия утечки секретов. Камера/реальная оплата требуют отдельных проверок; не считать эмуляцию банковской операцией.
5. Подготовка карточек Google Play и передача в тестирование после регистрации владельца. Публичная публикация — отдельный наблюдаемый результат, а не синоним сборки AAB.

Текущий фактический результат фиксируется в `docs/verification.md`; пункты выше — критерии, пока не подтверждены проверками.

## Google Play: внешние зависимости

Владелец выбрал бесплатную раздачу подписанных APK по ссылке; Google Play отложен. APK и будущие обновления должны сохранять ключ подписи. При последующем включении Play App Signing нужно использовать существующий ключ приложения (либо отдельно спланировать переход), иначе установленные APK не обновятся обычным способом.

Для будущей регистрации владелец выбрал личный аккаунт. Регистрация выполняется на [Google Play Console](https://play.google.com/console/signup): разовый сбор $25, соглашение, подтверждение личности и контактов выполняет владелец. Для новых личных аккаунтов нужны проверка настоящего Android-устройства и закрытый тест с минимум 12 участниками непрерывно 14 дней перед запросом production-доступа. Эмулятор не заменяет эту проверку владельца.

До публичного выпуска нужно согласовать и разместить реальную политику конфиденциальности; реализовать доступный запрос удаления аккаунта с описанием обязательного хранения финансовых документов; проверить жалобы/модерацию пользовательских отзывов; заполнить Data safety, возрастной рейтинг и доступ ревьюерам по фактическому поведению. Нельзя обозначать эти пункты выполненными по наличию этого документа. Native signup/reset остаются отдельной работой; приложение предлагает открыть соответствующую страницу сайта, затем вернуться и войти с созданным аккаунтом. Доступность восстановления зависит от серверного SMS-провайдера. Отдельный платёж за физическое проживание не переводится в Play Billing.

Официальные требования, проверенные 10.11.2026: [регистрация](https://support.google.com/googleplay/android-developer/answer/6112435?hl=ru), [закрытый тест](https://support.google.com/googleplay/android-developer/answer/14151465?hl=ru), [проверка устройства](https://support.google.com/googleplay/android-developer/answer/14316361?hl=en), [target API](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en), [удаление аккаунта](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en), [UGC](https://support.google.com/googleplay/android-developer/answer/9876937?hl=en), [платежи](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en).

## Команды разработки и подписи

```sh
npm ci
npm run android:signing:init  # один раз; сохраняет существующие ключи
npm run android:apk
npm run android:staff:apk
npm run android:test         # нужен Android Emulator/устройство
npm run android:staff:test
npm run android:open         # при установленном Android Studio
```

Нужны JDK 21 (Capacitor Filesystem toolchain), Android SDK platform 36 и build-tools 35.0.0/36.0.0 и доступный adb. Локальный путь SDK — в игнорируемом local.properties, либо ANDROID_HOME. Частные ключи и пароли — native/android/signing, права 0700/0600. Сделать закрытую резервную копию этого каталога; потеря ключа не исправляется генерацией нового для обычного обновления APK. Не отправлять файлы в чат или GitHub. Приложение не содержит ключ подписи, DB/S3/API secrets.

Проверенный release APK и SHA256 помещаются в output/android. После загрузки в GitHub Release проверяются публичные ссылки и совпадение SHA256. Официальный Google Play URL не выдаётся вместо ссылки APK. Для будущего AAB после соответствующего release sync: node scripts/build-android.mjs guest bundle (или staff bundle).
