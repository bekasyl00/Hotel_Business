## Сборка общего релиза после завершения кабинета

Гостевая ветка `codex/guest-booking-20261120` содержит проверенный код. Рабочая ветка кабинета `codex/staff-planner-reviews-20261120` развивается в отдельном worktree. После готовности кабинета:

1. Зафиксировать его проверенные изменения. Создать общую release-ветку от актуального `origin/main` и влить обе ветки. Сохранить гостевую логику доступности, цены, скрытия брони и документов вместе с новыми сценариями сотрудников. Общие файлы требуют проверки: `booking/{availability,models,serializers,services,views}.py`, `demo.js`, `WorkspacePage.vue` и архитектура.
2. Свести миграции `booking` к одной вершине. Гостевая `0023_booking_guest_hidden_at` добавляет nullable-поле; кабинет отдельно готовит `0023_staff_review_notification`. Если вторая ещё нигде не применена, переименовать её в `0024_staff_review_notification` с зависимостью от гостевой `0023`. Если уже применена, сохранить её имя и добавить merge migration с обеими зависимостями.
3. На объединённом коммите прогнать `npm test`, `npm run build`, `npm run build:surfaces`, `npm run build:release`, `npm run arch:check` и Django-тесты `booking commerce` на PostgreSQL с `makemigrations --check --dry-run`. Собрать отдельные гостевой и рабочий артефакты по [frontend.md](frontend.md).
4. Сверить состояние миграций нужной БД, сохранить резервную копию, затем применить миграции. Собрать API с `node scripts/package-api.mjs --deploy` по [backend.md](backend.md). Проверить конфигурацию кандидата на отсутствие маршрутов сайта и после promotion проверить каталог, календарь и авторизацию через стабильный API.
5. Отправить объединённый коммит в `main`. Гостевой Vercel связан с GitHub и собирает `main` автоматически, поэтому этот push следует после готовности API. Рабочий сайт выпустить из `dist/staff` в проект `tynys-staff` с конфигурацией рабочего артефакта. API, обе сборки и GitHub должны соответствовать одному коммиту.
6. Проверить с опубликованных адресов каталог, календарь с переходом месяца, вход сотрудника и приватность закрытых API. Зафиксировать SHA и deployment IDs. Временная регистрация по телефону и паролю без SMS остаётся действующей настройкой.
