# Tynys: пакет подготовки боевого запуска

Статус 14.11.2026: **NO-GO**. Подписки не заменяют оставшиеся интеграции и приёмку.
Инструкция включения подготовленных OTP/native API, restore и коротких кодов: [activation.md](activation.md).
Единый реестр остаётся [docs/production-readiness.md](../../docs/production-readiness.md), R01–R34.
Этот файл — конкретная схема закупки и переключения, а не второй backlog.
Действующие данные и сервисы не переносились; ничего платного не заказано.

## Решение для первого коммерческого пилота

Предложение: PS Cloud Services, площадка **в Казахстане**, с письменным подтверждением региона primary, replicas, резервных копий, S3 и журналов. Не выбирать площадку в Узбекистане по умолчанию. Конкретные SKU, SLA и стоимость получить до оплаты.

| Компонент | Сервис / размещение | Что готовим и покупаем |
|---|---|---|
| Домен и DNS | PS.kz, домен выбирает владелец | Основной домен, www, staff, api; MFA, автопродление; название ещё не куплено |
| Публичный и staff сайт | Nginx на PS Cloud app VM, отдельные virtual hosts | Статические dist/site и dist/staff; HTTPS; /api проксируется в Django; никогда не LikeC4 |
| Django API | PS Cloud app VM, контейнер из backend/Dockerfile | Отдельный staging, закрытая админка, TLS, health, restart, ограничения памяти/CPU |
| PostgreSQL 17 | Отдельная VM PS Cloud в private subnet | Не публичный 5432; администрирование PostgreSQL — наша ответственность, managed DB не предполагается |
| Файлы | PS Cloud S3, private buckets отдельно для staging/prod | Фото/видео/документы; доступ через существующий авторизованный MediaAsset API, не открывать bucket |
| Резервирование | Отдельный закрытый backup bucket в КЗ | PostgreSQL base backup + WAL, versioning файлов; шифрование и независимая копия ключей документов |
| Очередь | Существующие durable jobs в PostgreSQL | Отдельный supervised обработчик/таймер; сохранить leases, retries, reconciliation; не добавлять Kafka/Redis без необходимости |
| Метрики | Существующий bekasyl00.grafana.net, Grafana Cloud Free | Только обезличенные агрегаты; uptime, scheduler, queue age, DB connections, disk, ошибки оплат; тестовое письмо владельцу |
| Коды входа | SMSC.KZ HTTPS API как базовый канал | Договор, sender name, баланс, лимит трат; подтвердить доставку на операторах РК |
| WhatsApp OTP | Meta WhatsApp Business Platform, дополнительный канал | Business Portfolio, WABA, отдельный номер, одобренный authentication template, серверный token. Не автоматизировать личный WhatsApp |
| Оплата | Существующий XPayment v2 / Kaspi merchant | Уточнить тариф/лимиты/условия возвратов в своём кабинете; касса и юрлицо должны соответствовать договорной модели |
| iOS | Apple Developer Program / App Store Connect | Членство, App ID capability, APNs key/profiles, TestFlight, review; membership не публикует приложение автоматически |
| Android | Подписанные APK GitHub Releases сейчас | Ключи подписи сохранить; Play Console отдельным этапом |

WhatsApp-сообщение с кодом — не SMS. SMSC и WhatsApp имеют отдельные расходы и требования. Не считать бесплатное приложение WhatsApp Business API-провайдером.
Текущие local notifications на iOS/Android и браузере не доставляют новые запросы в полностью закрытое приложение. Будущие APNs/Web Push/FCM — отдельная интеграция, сейчас не включаем их вопреки принятому local-only режиму. FCM как канал сам по себе бесплатен, если владелец позднее разрешит его использование.

## Почему не просто купить Supabase Pro и оставить всё как есть

Сейчас сайт/staff/API работают на Vercel; БД/файлы по предыдущим проверкам — Supabase, регион вне КЗ. Текущий регион/резервирование в кабинете в этом проходе повторно не проверялись.
Статья 12 закона РК содержит требование о хранении персональных данных в базе на территории РК. Юрист должен подтвердить карту данных, трансграничную обработку, согласия и подрядчиков. До этого Supabase не назначаем боевым хранилищем ИИН и документов. Supabase можно сохранить для синтетического staging, не копируя туда production.
Vercel Hobby не подходит для коммерческого использования. Альтернатива: Vercel Pro для фронтенда после согласования трансграничной обработки и proxy-логов. Основной стартовый вариант выше — весь data plane в КЗ, без обязательной покупки Vercel Pro/Supabase Pro.
Google Cloud не выбираем только из-за студенческой Gemini-подписки: это отдельные сервисы и биллинг.

## Стартовый размер и бюджет

Ориентир для расчёта, НЕ доказанная ёмкость: app VM 2 vCPU/4 GB, DB VM 2–4 vCPU/8 GB и SSD 80–100 GB; размер подтвердить нагрузочным тестом. Начать с 1–2 санаториев. У одиночных app/DB VM нет HA; для SLA без простоя нужен отдельный бюджет на второй app, load balancer, PostgreSQL standby/failover и дежурство. Не обещаем миллионы пользователей и не включаем sharding заранее.

Формула ежемесячного бюджета: app VM + DB VM + диски/IP/трафик + S3 + независимые backups + SMS/WhatsApp + XPayment + эксплуатация. Отдельно домен, Apple, юридическая работа, публикация магазинов. Конкретный счёт PS Cloud и XPayment пока НЕ получен: не выдавать оценку за тариф. Grafana Free можно оставить в пределах лимитов.

## Что нужно владельцу оформить

1. PS.kz: аккаунт организации/владельца, MFA, выбранный домен, запрос расчёта по схеме выше. Получить регион, цену, SLA, поддержку pg extensions, backup/restore и S3 lifecycle/versioning. Не оплачивать managed PostgreSQL, пока поставщик письменно не подтвердит такую услугу.
2. SMSC.KZ: зарегистрировать проект/отправителя и получить тестовый баланс, тариф авторизационных сообщений. WhatsApp подключать официально и иметь SMS fallback.
3. XPayment: подтвердить текущую подписку, merchant, лимиты успешных/неуспешных счетов, signed webhooks, status lookup, partial refunds и поддержку. Не повторять неоднозначные платежи/возвраты.
4. Apple: оформить членство самостоятельно, принять договоры, предоставить доступ команде. Не присылать пароль/OTP.
5. Договоры с санаториями, оферта, политика данных, согласия, схема комиссий/возвратов/фискализации. Наш PDF не становится официальным фискальным чеком от добавления печати.
6. Секреты вводить только в закрытые серверные настройки/secret manager. Ключи, ранее опубликованные в переписке, заменить с проверкой перехода и отзывом старых.

## Технические работы до оплаты, которые нельзя считать завершёнными

- R07/R08: SMSC adapter, shared phone/IP/daily quotas и native challenge/register/reset реализованы. Настроить sender/API key/баланс, затем принять реальную доставку и reset на устройствах. Daily quota ограничивает попытки отправки, а не тенге/число SMS-сегментов: денежный лимит дополнительно поставить в кабинете провайдера. Временная поставка сохраняет явный flag регистрации без SMS; строгий production-preflight намеренно её отклоняет до подключения SMS.
- R02/R05: generic S3/env контракт, проверка PS endpoint и миграция private files. Текущий MEDIA_STORAGE=supabase использует S3, но имя настроек привязано к Supabase; совместимость PS не доказана.
- R04/R15: production deploy/rollback, отдельный worker/scheduler, heartbeat и гарантированное освобождение холдов. Не запускать worker копированием curl с секретом в командной строке.
- R09/R10: приёмка удаления аккаунта/retention и MFA операторов, анализ доступа к персональным данным.
- R16–R20: частичный возврат, сверка поздних оплат, документы/фискализация и реальная касса — сквозная приёмка.
- R25–R34: восстановление backups вместе с ключами шифрования, нагрузка, доступность, сообщения об авариях, актуальность мобильных сборок.
- Интегрировать накопленные изменения рабочего дерева в reviewable commits: опубликованные APK собраны из рабочего дерева, release tag пока не является полным исходником сборки. Нужен воспроизводимый release из чистого commit SHA.

## Порядок запуска после получения доступа

1. Зафиксировать scope пилота, договоры и разрешённую карту данных. Получить домен, регионы и секреты вне чата.
2. Поднять staging в КЗ с синтетическими данными. Собрать immutable image и два фронтенда из одного чистого SHA; сохранить предыдущие версии.
3. Восстановить тестовую копию PostgreSQL с extensions/constraints, проверить grants, sequences, migration drift. Скопировать файлы со сверкой размеров/хешей и стабильных MediaAsset ID. Отдельно проверить decrypt документов с keyring.
4. Подключить SMS/WhatsApp в sandbox/test; затем реальные малые проверки по согласованию. Доставка не равна подтверждению владения номером: только одноразовая успешная проверка challenge.
5. Настроить HTTPS/DNS, CORS/CSRF, secure cookies, native API origin, signed webhooks, worker, мониторинг. При изменении origin выпустить мобильные обновления, поддержать старые клиенты или назначить обязательное обновление до отключения старого API.
6. Пройти приёмку: параллельная бронь одного места; online/onsite сумма; paid/late-paid/expired; полный и частичный refund; check-in/out; roster; document release; чужой tenant denied; OTP/reset; uploads; restore; scheduler outage.
7. Репетиция переключения: сохранить исходную БД, кратко запретить новые записи, дождаться/сверить in-flight payments, остановить старого writer, финальная синхронизация, включить новый writer. Никогда два независимых production writer.
8. Переключить DNS/webhook на один активный API. После новых записей rollback не сводится к возврату старого DNS: сначала сверить/перенести новые брони и платежи. Не откатывать financial state вслепую.
9. Ограниченный пилот, мониторинг и ежедневная сверка. Расширение только по замерам. Создать incident runbook с ответственным и временем реакции.

## Проверка настроек без подключения к серверам

```sh
backend/.venv/bin/python scripts/production-preflight.py --env-file /private/path/production.env
```

Команда ничего не разворачивает и не выводит значения секретов. Код 1 означает блокирующие настройки, 2 — не удалось прочитать конфигурацию. Код 0 означает только прохождение ограниченной проверки конфигурации, а не готовность к запуску. Флаги verified нельзя выставлять ради зелёного результата: сначала приёмка провайдера. Пустая конфигурация ожидаемо отклонена; тесты проверки не требуют живой БД.
