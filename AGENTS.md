# Project navigation

Read `architecture/system.c4`, `architecture/modules.c4`, and recent `docs/decisions.md` before structural changes. Product scope and proposed backlog: `docs/product.md`. Current checks and limitations: `docs/verification.md`. Verify documentation against source.

- Vue 3 + Pinia + Vue Router + Vite, FSD, vue-i18n (ru/kk/en). Translation JSON lives in src/shared/i18n/locales; preserve key/placeholder parity. Backend: Django 5.2 / DRF / PostgreSQL in backend/. Read docs/backend.md.
- FSD dependencies: app → pages → widgets → features → entities → shared. Import another slice through its root public API; no sideways imports. `npm test` checks local JS/Vue imports.
- `src/app/providers/demo.js` implements the demo transport. `src/shared/api` owns the HTTP boundary. Contract: `docs/api-contract.md`. Views never access localStorage directly.
- `src/entities/booking/model/rules.js` owns date rules. Production validation and transactions live in backend/booking/services.py. PostgreSQL tests must use real PostgreSQL, never SQLite.
- Roles in the frontend are not security. Production tenant scoping, authentication, concurrency protection and audit integrity belong on the server.
- Keep fictional prices, approximate locations and illustrative photos explicit. No real personal data, credentials or payments in demo storage.
- Structural changes update the architecture in the same commit. `npm run arch:sync` derives FSD dependencies from local imports; semantic responsibilities are maintained in `system.c4`.
- Run `npm test`, `npm run build`, `npm run build:surfaces`, `npm run arch:check`. Check affected UI at desktop and mobile widths. Publish only the selected website artifact: public `dist/site` or staff `dist/staff`, never LikeC4. Build-time #surface-routes alias chooses public/staff/combined routes; see docs/frontend.md.
- Retired vanilla `src/app.js`, `src/map.js`, root styles and vendored Leaflet are replaced by Vue/FSD and package imports; do not restore them.

- Guest booking requires GuestAccount; name/phone come from its profile, never browser identity fields. Commercial bookings start pending (awaiting payment) with a 15-minute hold capped at check-in. Successful server-side payment atomically changes them to confirmed; manual confirm/reject is forbidden. Expired unpaid holds release inventory; never confirm from a browser redirect. Demo payments are still simulators, not bank events.
- Run backend tests with `backend/.venv/bin/python backend/manage.py test booking commerce`; include migration drift check. Never put credentials in source, audit, or logs.
- `backend/commerce` separates the internal simulator, Halyk/XPayment sandbox and scoped XPayment production payments. Live creation is server-gated by provider configuration and XPAYMENT_PRODUCTION_RESORT_IDS (currently Altyn Bulak/altun and Көктерек/kokterek); historical attempts retain provider/environment/merchant binding. Signed callbacks only queue independent server verification. Never repeat an ambiguous external create/refund POST; recover through authenticated lookup and durable jobs. Freeze check-in terms at booking creation. Refund schedule: >=48h 100%, >=24h 70%, otherwise 0%, applied only to the captured online amount; same for staff/guest. Demo cancellation/refund commits atomically; real refund is complete only after verified provider evidence.
- GuestAccount is separate from staff User. Registration/reset requires a challenge; demo OTP must require DEBUG plus GUEST_AUTH_DEMO_OTP. All guest ownership checks use guest_owner, including receipts and payments; reset invalidates earlier sessions. Never merge accounts/bookings by phone alone.
- Native guest sessions use booking/mobile_auth.py and identity models: short-lived opaque access tokens, rotating refresh tokens, replay revocation, account auth-version and per-device revocation. A Bearer token never grants staff access; invalid Authorization must not fall back to cookies. Browser writes still require CSRF. Versioned /api/v1 and legacy /api use the same handlers. Native registration/reset transport and real SMS remain outstanding; see docs/mobile-api.md.
- New uploads have MediaAsset metadata and stable authorized /api/media/files/:id URLs. Keep default storage private (local private-media or configured Supabase S3); never expose storage keys or persist expiring signed URLs. Catalog/review references must pass media_access ownership validation. Avatars require a signed-in guest. cleanup_media is dry-run by default; deletion must retain referenced files. Supabase configuration is not evidence of a live connection.
- Django Admin is /django-admin/ (/admin/ redirects), served by platform_admin_site and restricted to active staff superusers. Domain models are read-only there; mutations use service-backed staff workflows. Do not restore unrestricted UserAdmin or expose password/token/ownership hashes. See docs/admin.md.

- Two Capacitor iOS apps: guest `mobile` → dist/mobile → ios/ (kz.tynys.booking); staff `mobile-staff` → dist/mobile-staff → ios-staff/ (kz.tynys.staff). Keep audience routes and links isolated. Shared native bridge in native/ios. Run `npm run build:apps`; native checks `npm run ios:check` and `npm run ios:staff:check` after corresponding sync. See docs/ios.md.
- Native staff uses separate StaffDevice/StaffRefreshToken and /staff-mobile-auth; guest Bearer still never grants staff access. Staff credential versions invalidate password/role/resort changes. Native credentials only in Keychain, never browser storage/logs. Do not enable remote server.url, cleartext or broad ATS exceptions. Demo stores in the two apps are independent; never claim live cross-device synchronization without deployed API proof.

- Canonical remaining-work register: docs/production-readiness.md R01–R34; proposed capacity/SRE targets in docs/sre.md are not measured capacity. Benefit entitlement, budget funding and official documents are separate planned domains, not booking/payment status flags. No inferred government eligibility or invented government API.
- booking/pricing.py owns per-night seasonal + opt-in under-three tariff pricing. RoomPricePeriod excludes overlapping room ranges; edits share resort lock. Quote/snapshot rounds each night, total sums nights, nightly is null for nonuniform prices. Existing snapshots are immutable. Children count towards capacity and require an adult. User-selected demo checkout accepts 12 digits in component memory and derives a tentative birth date from the first six; no identity verification or official eligibility is implied. Never transmit/persist/log the full IIN; server recomputes age from transient DOB and stores ages only.
- User deferred Android and iPhone rebuilds until a later delivery; do not sync/install native builds for ordinary web/backend work unless asked.

- Only platform admins can set per-resort commissionPercent (nullable, 0–100, two decimal places); public bookingFeePercent is read-only. New bookings require a positive configured rate and freeze paymentTerms v1: onlineAmount is half-up rounded markup above accommodationTotal, onsiteAmount equals accommodationTotal, total is their sum. Booking.total remains accommodation for compatibility. Legacy snapshots without terms derive v0/full-online/onsite=0 and are never backfilled. Charge/refund only frozen onlineAmount. Staff-only commissionTerms use accommodation_markup; never treat estimates as bank splits/payouts.
- Owned booking vouchers are ticket JSON/PDF, not provider/fiscal receipts; paid/refunded history remains accessible with current validity status. OnsiteSettlement is one protected staff attestation per booking, not a bank event: admin/owning manager only, frozen amount, version/method/received validation, local stay dates, resort lock, idempotency and audit. Recorded onsite collection blocks ordinary cancellation and is required before new fee-based check-in. Invoice/act base and paidAmount represent accommodation/onsite collection; platform fee and refund remain separate. Never include onsite attestations in platform received/net or rewrite released documents.

- Staff `/staff/bookings` defaults to the room planner. Colors use actual stay/payment state, never infer check-in/out from elapsed dates. Staff room-only booking omits tariffId; public/legacy explicit tariff pricing remains. Preserve old price snapshots. Booking.tariff is nullable since 0009. Staff notes are scoped/versioned and never exposed to guests or duplicated in audit; see docs/api-contract.md.

- Accountant is platform-wide (user decision 2026-11-08), independent of resort assignment. Explicit accountant read permissions cover workspace/planner and analytics, with no operational mutations or account management. Accounting writes stay admin/accountant-only. Managers read documents only for their own bookings; guest files remain owned/released only.
- AccountingExpense is manual whole-KZT incurred-cost tracking, segregated production/sandbox/demo. Creation uses a unique request key; immutable corrections use versioned void with reason/audit. Reports separate cash events, orders, expenses and commission estimates; never call net receipts profit or bank balance. Current exports are not a 1C integration or registered ESF.

- Resort.account is mandatory (PROTECT). A manager may own multiple resorts; User.resort is legacy and never grants scope. Ownership changes only via admin versioned resort workflow; account role/ownership changes share an advisory transaction lock and bump User.version to invalidate native credentials. Seed requires an existing admin. /clients is platform-admin-only; guest access changes bump auth_version, preserve history, and never merge by phone. Guest /profile UI requires actual GuestAccount login.

- Document identities are separate staff-only encrypted `DocumentGuestRoster` data, not guest checkout/profile fields. Never log/copy full IIN into booking snapshots, public/workspace lists or Audit. Only a frozen encrypted buyer is used by authorized exports; released documents remain immutable. `DOCUMENT_DATA_ENCRYPTION_KEYS` is a server-only Fernet keyring, never derived from authentication secrets. Keep roster RLS/private grants and review key backup/retention before real rollout.
- Audit history is admin-only, including workspace API and direct frontend routes. Admin changes to staff email/version/role revoke browser and native sessions. Account editing belongs to service-backed staff workflows, not unrestricted Django Admin.
- Guest displayed prices include the platform markup; hide the internal percentage from UI. Clearly separate full total, pay-now amount and amount due at property. Actual payment/refund/receipt amounts remain the collected online amount; never present full stay price as bank funds received.
